# PN Infinity — Pancake Dashboard (เวอร์ชัน Full-stack)

เวอร์ชันใหม่ที่ย้ายจาก Google Apps Script + Google Sheet มาเป็น **Supabase (Postgres) +
GitHub Actions (cron) + Next.js (Vercel)** — เร็วกว่า เสถียรกว่า และยังฟรี

```
GitHub Actions (cron ทุก 15 นาที)
      │ รัน Node script
      ▼
Sync Worker (TypeScript)  ──fetch──▶  Pancake POS + Pages API
      │ เขียน
      ▼
Supabase Postgres (มี index → เร็ว)
      ▲ อ่าน
      │
Next.js Dashboard บน Vercel
```

## โครงสร้างโปรเจกต์

```
pancake-dashboard/
├── db/schema.sql          โครงตาราง Postgres (รันใน Supabase ครั้งเดียว)
├── lib/
│   ├── config.ts          ค่าคงที่ + helper วันที่ (โซนไทย)
│   ├── pancake.ts         HTTP client เรียก Pancake API
│   ├── mappers.ts         แปลงข้อมูลดิบ → แถวตาราง
│   └── supabase.ts        client เขียน DB + upsert/log/state helper
├── scripts/               (เฟส 2) sync worker + setup scripts
├── app/                   (เฟส 3) Next.js dashboard
└── .github/workflows/     (เฟส 2) cron
```

## 🩺 ระบบเฝ้าระวังข้อมูล (อย่ารื้อโดยไม่อ่าน)

ปัญหาที่แพงที่สุดของระบบนี้ไม่ใช่ "งาน sync ล้ม" แต่คือ **งาน sync บอกว่าสำเร็จทั้งที่ทำงานไม่ครบ**
(ส.ค. 2026 เจอติดกัน 4 เคส ทุกเคสขึ้นเขียวหมด กว่าทีมจะจับได้ก็ผ่านไปเป็นสัปดาห์) จึงมี 3 ชั้นนี้:

| ชั้น | ไฟล์ | ทำอะไร |
|---|---|---|
| ตรวจกุญแจก่อนเริ่มรอบ | `scripts/sync/envcheck.ts` | ขาดค่าจำเป็น = หยุดทั้งรอบ + เขียน log, ขาดค่าฟีเจอร์ = ฟ้องแต่ไปต่อ — ห้ามให้งาน "ข้าม" ตัวเองเงียบๆ |
| ใบรายงานผลของแต่ละงาน | `lib/jobstat.ts` | งานคืน **ตัวเลข** (`unitsOk/unitsFailed/rowsWritten/skipped/scope`) ไม่ใช่ข้อความไทยล้วน แล้วเก็บลง `sync_state` คีย์ `job_stat:<งาน>` |
| ตรวจว่าเลขที่ได้เป็นไปได้ไหม | `scripts/sync/invariants.ts` | รันปิดท้ายรอบ hourly/daily — ผิดข้อไหนเขียนเป็นงาน `invariants` ล้มลง `sync_log` |

กฎที่ตรวจอยู่ (ทุกข้อคิดจาก "เมื่อวาน" เพราะวันนี้ยังเดินอยู่): มีออเดอร์ • สถิติแชทครอบคลุมเพจที่มีออเดอร์ ≥70% •
%ปิดการขาย ≤100% • มีค่าแอดแล้วต้องมีคนทัก • %ปิดจากแอด ≤150% • กำไรจากชีทไม่ค้างเกิน 2 วัน •
ไม่มีแถว "วันอนาคต" • ทุกงานไม่พลาดเพจเกิน 1 ใน 3 และแถวไม่หายเกินครึ่งจากรอบก่อน

ทีมเห็นผลที่ **ชิปบนหัวเว็บ** (`⚠️ งาน sync มีปัญหา N งาน` — ชี้เมาส์ดูรายละเอียด) และในแถบข้างซ้าย
โค้ดฝั่งอ่านอยู่ที่ `lib/api/bootstrap.ts` (`syncHealth`)

> เพิ่มงาน sync ใหม่: คืน `jobResult(ข้อความ, { unitsTotal, unitsFailed, rowsWritten, scope })` แทน `return 'ข้อความ'`
> ถ้าทำงานไม่ได้เพราะขาดของ ให้ใส่ `skipped` (จะถูกนับเป็นไม่สำเร็จ) — อย่า `return 'ข้าม: ...'` เฉยๆ

## 📱 หน้าตาเว็บ: mobile first (อ่านก่อนแก้ CSS)

ทีมเปิดเว็บนี้จากทั้งคอมและมือถือหลายรุ่น และ**ทำงานได้ทุกอย่างจากมือถือ** ไม่ใช่แค่ดู
`app/globals.css` จึงเขียนแบบ mobile first — สไตล์ที่อยู่นอก `@media` คือหน้าตาบนมือถือเสมอ

| กติกา | เหตุผล |
|---|---|
| **ห้ามเขียน `@media (max-width: …)`** ถ้าต้องซ่อนของบนมือถือ ให้ตั้งค่าเริ่มต้นเป็นซ่อนแล้วเปิดใน `min-width` | เขียน max-width เมื่อไหร่ ไฟล์ก็กลับไปเป็น "เดสก์ท็อปที่ค่อยๆ พัง" เมื่อนั้น |
| **มี 3 จุดตัดเท่านั้น: `600` / `900` / `1200`** ห้ามเพิ่ม | เดิมมี 9 จุด (560/640/700/720/860/900/1100/1180/1280) ไม่มีใครจำได้ว่าอันไหนคุมอะไร |
| **คอลัมน์กริดเขียน `minmax(0, 1fr)` เสมอ** ห้าม `1fr` เปล่า • `repeat(auto-fit, minmax(min(280px, 100%), 1fr))` | `1fr` มีค่าต่ำสุดเป็น auto ตารางกว้างจึงดันทั้งหน้าเกินจอ • `min(…, 100%)` กันจอ 320px |
| **ระยะห่างใช้ `var(--sp-1..8)` ตัวอักษรใช้ `var(--fs-1..8)`** ห้ามใส่ px ลอย | เดิมมีระยะห่าง 21 ค่า/ตัวอักษร 25 ขนาด การ์ดข้างกันจึงเว้นไม่เท่ากันโดยไม่มีเหตุผล |
| ยกเว้น 2 จุดที่ต้องเป็น **`16px` ตายตัว**: `.input` และ `.login-input` | ต่ำกว่า 16px แล้ว iOS ซูมเข้าเองทุกครั้งที่แตะช่องกรอก |

**ตารางบนมือถือ** จัดโดย `classifyTable()` ใน `lib/ui/app-core.ts` (ดูจำนวนคอลัมน์ตอน render เสร็จ
ผ่าน MutationObserver — ไฟล์ view ไม่ต้องแก้อะไร):

- ≤3 คอลัมน์ → ตารางธรรมดา
- 4-8 คอลัมน์ → `.tbl-cards` = 1 แถวเป็น 1 การ์ด หัวคอลัมน์กลายเป็นป้ายกำกับซ้าย ค่าอยู่ขวา
- ≥9 คอลัมน์ → `.tbl-scroll-x` = เลื่อนแนวนอน ตรึงคอลัมน์แรกไว้
- บังคับแบบไหนเองก็ได้ด้วย `data-cards="off"` + คลาสที่ต้องการบน `<table>`

**แถบเมนู** กว้าง 250px คงที่ ซึ่งบนแท็บเล็ต (iPad แนวตั้ง 1024px) กินไปหนึ่งในสี่ของจอ
ปุ่ม ☰ จึงใช้ได้ทุกขนาดจอ: จอ <900 = เปิด/ปิดลิ้นชัก • จอ ≥900 = พับ/กางแถบเมนูที่ปักซ้าย
จำค่าที่เลือกไว้ใน `localStorage['pn-nav']` — ยังไม่เคยเลือก: จอ ≥1200 กางไว้, แคบกว่านั้นพับไว้

**โมดัลบนมือถือ** เป็นแผ่นเลื่อนขึ้นจากขอบล่าง (`<600px`) — ปิดได้ 3 ทาง: ปุ่ม ✕ / แตะฉากหลัง /
**ลากหัวแผ่นลง** (`bindSheetDrag_` ใน `lib/ui/helpers.ts` — เกิน 1/4 ของความสูง หรือสะบัดเร็วกว่า 0.6 px/ms)
จับเฉพาะ `.modal-head` ที่ตั้ง `touch-action: none` ไว้ ส่วนเนื้อหายังเลื่อนได้ตามปกติ
> ⚠️ อย่าใส่ "ขีดจับ" ให้กล่องที่ลากไม่ได้ — ของที่หน้าตาเหมือนจับได้แต่จับไม่ได้ แย่กว่าไม่มีขีดเลย

**วัดก่อน-หลังเสมอ** อย่าเชื่อสายตา:

```bash

node scripts/dev/mobile-audit.mjs 360 780      # หน้าไหนล้น กี่ px ต้นตอคืออะไร + ปุ่มที่เล็กเกินเกณฑ์
node scripts/dev/mobile-smells.mjs 412         # อาการที่ "ไม่ล้นแต่ยังพัง": ตัวเลขโดนตัด, ล้นออกนอกกล่องแม่,
                                               # กริด ≥3 คอลัมน์บนจอแคบ, ตัวอักษรต่ำกว่า 11px
node scripts/dev/check-contrast.mjs            # คอนทราสต์ทั้งสองธีม
```

> วัดที่ **412px ด้วย** ไม่ใช่แค่ 390 — จอ Android ส่วนใหญ่กว้าง 412 ซึ่งพอดีกับที่กริดขยับจาก
> 2 เป็น 3 คอลัมน์ ปัญหาหลายอย่าง (ตัวเลขเงินโดนตัด) โผล่เฉพาะตอน 3 คอลัมน์

**กราฟ SVG:** ตัวหนังสือในกราฟอยู่ในหน่วย viewBox มันย่อไปพร้อมกราฟ — เขียน 11px แต่บนมือถือ
เห็นจริงแค่ ~5px แก้ด้วย CSS ไม่ได้ `vbWidth()` ใน `lib/ui/charts.ts` จึงย่อ viewBox ลงบนจอ <600px
ให้อัตราย่อเข้าใกล้ 1 เท่า **อย่าเพิ่มกราฟใหม่ด้วย viewBox ตายตัว**

> ⚠️ ต้องรอหน้าโหลดข้อมูลจริงก่อนวัด (สคริปต์รอ 16 วิ/หน้า) — เคยวัดตอนยังเป็นโครงโหลดแล้วสรุปผิดว่า "ไม่ล้น"
> ⚠️ ห้ามสั่ง `npm run build` ตอน dev server รันอยู่ — เขียนทับ `.next` ทำ dev พังทันที

## เริ่มใช้งาน (สิ่งที่ต้องทำ)

### 1. ติดตั้ง dependencies
```bash
npm install
```

### 2. สร้างโปรเจกต์ Supabase (ฟรี)
1. สมัคร/เข้า https://supabase.com → **New project** (เลือก region ใกล้ไทย เช่น Singapore)
2. รอสร้างเสร็จ → เมนู **SQL Editor** → **New query** → เปิดไฟล์ [db/schema.sql](db/schema.sql) วางทั้งหมด → **Run**
3. เมนู **Project Settings → API** → copy 2 ค่า:
   - **Project URL** → `SUPABASE_URL`
   - **service_role** secret → `SUPABASE_SERVICE_ROLE_KEY`

### 3. ตั้งค่า environment
```bash
cp .env.example .env.local
```
แล้วกรอกค่าใน `.env.local` (Pancake keys ชุดเดิม + Supabase 2 ค่าจากข้อ 2)

### 4. (เฟส 2) รัน sync
```bash
npm run setup:pages   # ค้นหาเพจ + สร้าง token → เก็บใน DB
npm run backfill      # ดึงข้อมูลย้อนหลังครั้งแรก
npm run sync:fast     # ทดสอบ sync รอบสั้น
```

> คีย์ทั้งหมดอยู่ใน `.env.local` (ไม่ขึ้น git) และ GitHub Secrets — ไม่รั่วในโค้ด
